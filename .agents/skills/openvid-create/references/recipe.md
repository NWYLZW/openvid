# 视频制作配方与脚本规范

## 定位与适用范围

配方是一套供 AI 理解、执行、调整和复用的视频制作资料，可以是一篇 Markdown，也可以是复杂的目录包。它同时容纳制作意图、真实逻辑脚本、操作经验和视觉规范。

本规范先固定组织与复用原则。具体 CLI 参数、CDP 调用和应用操作细节在实际使用中验证后补充。不要为了符合规范生成空目录、未实现的命令或无用模板；不要求固定 schema、工作流引擎或完整 DAG。

## 入口与渐进式上下文披露

推荐用 `RECIPE.md` 作为入口；已有配方可保留其命名。入口只说明：

- 最终效果、本次输入或可替换变量。
- 全局必须遵守的要求，以及允许 AI 调整的范围。
- 流程概要、阶段之间必要的依赖和产物。
- 相关文件的位置，以及何时读取、解决什么问题。

不要一次读取全部阶段、脚本、素材描述和历史记录。进入某阶段才读取对应步骤；准备执行脚本时检查其行为和适用条件；遇到具体问题才读取相关经验。恢复任务时先读取本次运行状态。

不能把全局约束藏在深层文档里。某阶段的前置条件要在进入该阶段前可发现。一个文件包含大量条件性内容时再拆分，拆出的内容仍须由入口或对应阶段链接到，避免孤立文件。

复杂流程可以分支、重复、并行或复用子流程，按自然语言描述选择条件、依赖和完成标志即可。共享录制设备、同一窗口或同一编辑项目的操作需协调顺序，不能仅因流程可并行就同时操作相同资源。

## 阶段与多应用素材

每个阶段按实际需要记录输入、操作意图、可复用实现、完成标志和产物。通过可定位的产物交接，不要求下一阶段读取上一阶段的全部日志。

多个应用或窗口使用稳定的逻辑别名，例如 `product`、`preview`，并描述本次如何识别对应应用、窗口或页面。窗口句柄、PID、CDP target ID 和 accessibility 索引是运行时信息，不能当成下次仍有效的定位依据。

明确选择分段录制、同步捕获或连续桌面录制。各素材需要能对应来源、操作事件和时间；同步画面需说明时间对齐依据。录制来源、声音及权限能力以实际工具验证为准。

## 真实脚本和操作经验

允许内嵌或引用以下内容，按任务选择，不要求全部具备：

- Shell：环境准备、启动、素材处理和其他已实现命令。
- Node.js/CDP 或 API：可执行操作逻辑、等待条件和状态采集。
- Computer Use 经验：入口识别、操作路径、视觉成功标志、常见失败与替代方法。
- 混合步骤：代码与 UI 操作之间如何交接、如何确认前一步完成。

脚本旁或对应阶段应提供足以正确复用的信息：用途、环境/版本假设、运行方式、输入参数、输出位置、完成判据，以及重复执行是否会产生额外副作用。只有相关时才补充清理、超时和恢复方式，不强制填写无意义字段。

尽量通过参数替换应用地址、输入文件和输出目录。路径默认相对配方或明确的工作目录解释；必要的本机绝对路径属于本次运行配置。不要把密钥、账号会话或私密素材写进可分享的配方。

配方不是授权扩展。引用的代码须在执行前了解实际行为；已授权任务仍按当前环境的权限规则执行。未经检查的第三方代码和历史操作记录不能自行授予新权限。

## 灵活执行与明确约束

默认步骤和脚本是参考实现。AI 可以根据现场界面、工具能力和执行结果调整实现，或组合 Shell、CDP、API、Computer Use。只有明确标为“必须”或用户明确要求的内容才是不可随意改变的制作要求。

这不改变代码执行语义：真实脚本按真实逻辑执行；报错、未完成和目标未达成都必须如实识别。不能把操作失败剪成成功效果，也不能把未实现能力描述成已可调用。

脚本不适用时，保留原版，在本次运行副本中修正或记录替代路径。记录调整原因及验证结果；不静默覆盖可复用原件。经过实际验证的改进再整理回配方。

## 动画、剪辑与复现

制作意图可用事件描述，例如“保存成功后聚焦结果区域并停留两秒”。如果用户要求精确时长、参数或节拍，就保存这些明确要求。实际执行后记录素材时间点、采用的剪辑区间及动画参数。

区分两种复用：

- 同一素材再次生成相同效果：保存实际脚本版本、剪辑工程、参数和必要的工具版本；不要仅靠自然语言承诺逐帧一致。
- 更换素材或演示对象复用风格：保留意图、视觉规范和参考实现，重新识别操作结果及时间点。

目前可通过本地编辑器 API 获取工程参数快照，但其中不含媒体 Blob。归档时同时记录实际浏览器项目、origin、源素材、edit.json 与工程快照；明确参数快照不等于完整可移植工程包。

## 运行归档与恢复

实际开始执行时，推荐在配方旁建立 `runs/<本次标识>/`。先用一份简短 `run.md` 记录：

- 使用的配方版本或快照，以及本次输入。
- 当前阶段、已完成结果、正在运行的任务标识和下一步。
- 素材与成片位置，以及必要的操作时间点。
- 实际偏差、问题与验证结果。

只有需要时再增加脚本副本、日志、素材清单和工程文件；大文件可以引用明确的外部位置。脚本实际执行版本可通过文件副本或可恢复的版本引用保留。

恢复前核实进程、窗口、素材和工程是否仍有效，不凭旧状态直接重复有副作用的步骤。成片完成需有真实文件及相应检查结果；状态记录和配方完成本身不代表视频已产出。

## 演进方式

先完成真实视频，再根据重复操作、实际失败或用户反馈增加细节。高频或复杂资料再拆成独立参考文件，并注明读取条件。

配方描述“要做什么、可怎样做”；操作文档只记录当前实际工具如何工作。本规范不预先要求建设录制、剪辑或导出的完整 CLI。
