# 最小配方约定

小流程一个 `RECIPE.md` 就够。复杂到需要时才拆阶段、脚本、素材和经验文件，不强制 schema 或完整目录模板。

入口应说明目标、输入、必须遵守的要求、可调整范围，以及阶段和引用的读取时机。引用同时写“何时读”和“解决什么问题”；不要要求一次加载整个包。跨阶段的必要约束放在入口，局部步骤在阶段开始时披露。

阶段按需要注明：输入、操作意图、可复用实现、完成标志、产物。多应用录制要明确素材来源，以及分段录制、同步捕获或连续桌面录制的区别。当前录制工具和权限能力以实际验证为准。

真实脚本可以内嵌或引用独立文件。执行前了解行为、参数、环境要求及成功判据。选择器或接口变化时可修改本次副本或换用其他已授权工具；不要隐藏失败，也不要未经验证把经验写成确定能力。

优先用事件描述剪辑意图（“保存成功后停留两秒”），执行后记录实际时间和精确参数。需要确定时间或参数时可直接指定；只有明确要求才是硬约束。

当实际开始执行时，在配方旁建立 `runs/<本次标识>/`，用一份简短 `run.md` 保存当前阶段、实际输入/素材路径、已完成结果、偏差与下一步。需要时再增加实际脚本副本、操作时间点、剪辑工程和导出检查。恢复时先读这份状态，再读取当前阶段需要的文件，不重放全部历史。

同素材精确复现依赖实际工程与参数；换素材复用依赖意图、风格和可调整的操作实现。Openvid 还没有工程 CLI 时，不要伪造工程产物：记录实际浏览器项目、origin、素材和已采用参数即可。
